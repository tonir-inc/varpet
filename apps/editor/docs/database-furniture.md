# Database furniture

The editor starts with the editable apartment shell and no demo furnishings. Furniture search and category filters query the shared catalog database. The File menu restores an empty apartment. Procedural examples remain only for isolated fixtures and the local proposal example; database furniture never uses their geometry.

Run `pnpm dev`. The Vite development and preview servers expose read-only `/api/catalog/search`, `/api/catalog/items` and `/api/catalog/vocab` routes. They connect to `http://100.107.246.46:8765/mcp`, or the server-only `VARPET_CATALOG_URL` environment override. A static host must provide these routes separately. Restart Vite after changing the endpoint. The shared endpoint requires the team's network connection; database credentials never enter the browser. Each request has a 15-second server deadline. Failure shows an empty library and Retry; there is no sample-data fallback.

Search returns up to 20 ranked records. Supported floor-standing types map to existing editor kinds while retaining their database category. Wall-mounted products are omitted because furniture is floor-grounded. Only records with valid dimensions, AMD pricing, attribution and a GLB URL on the approved ABO host are offered. Product names are capped at the editor's 120-character limit.

Database dimensions `[width, depth, height]` become editor `[width, height, depth]`. `fit_size_m` takes precedence over raw mesh dimensions. When `wd_swapped` is true, width/depth and the model orientation rotate together; a `#varpet-rotate-y=90` fragment carries the renderer hint without changing the scene schema. Imported meshes are centered, grounded and scaled to fit dimensions. Conflicting sizes can therefore stretch a mesh; the product's size status remains visible and is not promoted to confirmed.

The Furniture panel loads actual GLB previews only for visible cards, with two concurrent downloads and a bounded 12-preview cache. Placement loads the same real models; a neutral box shows their measured bounds while loading or on failure. Comparison ghosts use those neutral bounds. No procedural sofa/chair is substituted for a missing database mesh. Product materials are retained unless the person explicitly sets a finish color. ABO models can be large (the checked sample was approximately 14.6 MB).

Prices show AMD and their database price source. ABO prices are mock amounts, not quotations. New projects use AMD. If an imported project uses another currency, ABO prices are excluded from its total and a review issue explains why; no exchange rate is invented. Attribution to Amazon Berkeley Objects and CC BY 4.0 is shown in the library and product inspector.

The store retains validated search results plus every catalog reference used by the current scene, its baselines/options, and undo/redo history. Unused earlier search results are discarded, so browsing thousands of products does not exhaust the catalog. Referenced entries cannot change sizes or prices during a session; browsing preserves revisions and undo/redo. Imports and local loads hydrate furniture IDs in the scene, baseline and saved options before validation. A failed resolution leaves the current project unchanged. Old exports referencing procedural demo IDs cannot be opened as database products. The existing 1,000-entry limit applies to the retained reference set and current results; save and reopen if accumulated project history reaches it.

Catalog-only verification: `pnpm --filter @varpet/editor test:catalog` checks mapping, dimensions/orientation, registration/history, invalid records, empty startup, snapshot hydration, currency handling, renderer resources, transport sessions/SSE, deadlines and error sanitization. Full verification and live connectivity evidence are recorded with the task output.
