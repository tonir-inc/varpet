# Pascal source review

Inspected 2026-09-26 at commit [`863f37e9988494677221ba13e6912da7564382da`](https://github.com/pascalorg/editor/commit/863f37e9988494677221ba13e6912da7564382da), dated 2026-09-25. Evidence below comes from the checked-out source, not screenshots. No Pascal code or assets were copied into Varpet. This was a source review: Pascal was not installed, built, benchmarked, or interactively tested.

**Decision: build the independent Three.js/TypeScript editor and adapt interaction ideas.** Pascal is a useful architectural reference, but replacing our Vite host would introduce its node model, React/R3F, Next peer dependency, and a much larger application surface. Keep Varpet's engine scene and checked operations as authority, with renderer previews outside the committed document.

## Verified findings

| Area | Source evidence | Implication for Varpet |
| --- | --- | --- |
| Application and dependencies | The app specifies React 19, Next 16, R3F/Drei and Three r186. The editor package exports source TSX and requires Next, React, R3F, core and viewer peers. [App manifest](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/apps/editor/package.json#L14-L57), [editor manifest](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/package.json#L6-L61) | Do not import the full editor package into the plain Three.js host. Compatible Three versions alone do not make the architectures interchangeable. |
| Scene model | Zod nodes have IDs, type, parent, visibility and metadata. Scene state is a flat node dictionary with root IDs, dirty IDs, materials and collections. Walls use planar endpoints; items use 3D transforms plus an asset descriptor and attachment metadata. [Base schema](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/schema/base.ts#L21-L37), [store](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/store/use-scene.ts#L1467-L1494), [wall](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/schema/nodes/wall.ts#L132-L192), [item](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/schema/nodes/item.ts#L78-L144) | Adapt ID-based render lookup, but do not adopt a competing scene schema. Store units/axes explicitly at our adapter boundary. |
| Persistence and history | Current source uses Zundo snapshots with a 50-action limit and commit notifications. Editor autosave calls a host callback or localStorage. The local service uses SQLite. Thus README's IndexedDB scene-persistence description is stale; IndexedDB remains used for asset storage. [History](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/store/use-scene.ts#L1813-L1841), [autosave](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/hooks/use-auto-save.ts#L96-L115), [save dispatch](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/hooks/use-auto-save.ts#L195-L205), [SQLite paths](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/mcp/src/storage/sqlite-scene-store.ts#L90-L115) | Keep persistence independent from rendering; verify save/load round trips and preserve previous data on failed imports. |
| Camera and input | Custom controls reserve left mouse for editing, middle for screen pan, right for orbit, and wheel for dolly/zoom. Touch behavior changes with tool/preview context. [Controls](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/components/editor/custom-camera-controls.tsx#L648-L710) | Adapt clear camera/edit gesture ownership and disable camera movement during manipulation. These bindings are source-verified, not usability-tested here. |
| Snapping | Explicit grid, lines, angles and off modes have context defaults. Pure math snaps X/Z while preserving Y, including conversion of world-grid results back into rotated building coordinates. Default angular interval is 15 degrees. [Modes](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/lib/snapping-mode.ts#L15-L94), [pure math](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/services/snap.ts#L17-L104) | Implement a small explicit snap policy, with a visible toggle. Never silently snap in a different frame from the visible grid. |
| Direct manipulation | Draft items isolate live movement from undo; commit restores the baseline before one tracked update, and cancellation restores original transforms. [Draft lifecycle](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/components/tools/item/use-draft-node.ts#L76-L81), [move commit](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/components/tools/item/use-draft-node.ts#L216-L269), [cancellation](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/components/tools/item/use-draft-node.ts#L346-L407) | Adapt preview/commit/cancel semantics. Our final commit must go through the engine checks and person approval required by the Constitution. |
| Architecture editing | Walls carry thickness, height, curved-wall offset and hosted door/window children. The renderer subtracts opening cutters using BVH CSG; node definitions also cover slabs, ceilings, roofs, zones and stairs. [Wall schema](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/schema/nodes/wall.ts#L132-L192), [opening subtraction](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/viewer/src/systems/wall/wall-system.tsx#L1437-L1462), [node sources](https://github.com/pascalorg/editor/tree/863f37e9988494677221ba13e6912da7564382da/packages/nodes/src) | For our rectilinear flat, segment walls around openings directly. Defer a general CSG architecture stack until required. |
| Assets | The catalog references external Supabase GLBs and thumbnails. Item descriptors include dimensions and corrective offset/rotation/scale. The loader enables compressed textures and Meshopt. No per-asset license field was found in the inspected asset schema; asset rights and availability were not verified. [Catalog](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/editor/src/components/ui/item-catalog/catalog-items.tsx#L20-L50), [descriptor](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/schema/nodes/item.ts#L78-L120), [loader](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/viewer/src/hooks/use-gltf-ktx2.tsx#L1-L15) | Reuse the normalization idea; use our own procedural catalog and explicitly supplied assets. Do not hotlink or redistribute Pascal catalog files on the strength of the repository license. |
| Rendering/performance | Viewer constructs a WebGPU renderer, ACES tone mapping, capped DPR, controlled frame loop and optional post-processing. Wall rebuilds use dirty state, an 8 ms budget and delayed adjacent-wall rebuilds during drags. Those are implementation mechanisms, not measured performance guarantees. [Viewer](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/viewer/src/components/viewer/index.tsx#L575-L640), [frame/post-FX options](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/viewer/src/components/viewer/index.tsx#L387-L407), [wall budget](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/viewer/src/systems/wall/wall-system.tsx#L600-L658) | Adapt capped DPR, resource reuse/disposal, selective rebuilding and diagnostic performance controls. Keep the initial renderer on familiar Three WebGL instead of adding WebGPU/TSL complexity. |
| Extension and maintenance | Plugin API version 1 accepts node definitions and inspector extensions. Loader rejects incompatible API versions. CI declares lint, typecheck, tests, build and CLI smoke checks. The inspected HEAD is recent; this does not establish release stability or a passing CI run. [Plugin contract](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/registry/types.ts#L989-L995), [loader](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/packages/core/src/registry/registry.ts#L380-L390), [CI](https://github.com/pascalorg/editor/blob/863f37e9988494677221ba13e6912da7564382da/.github/workflows/ci.yml#L13-L72) | A small internal object-factory interface is enough now. Keep future extension contracts versioned, and pin any external dependencies to inspected revisions. |
